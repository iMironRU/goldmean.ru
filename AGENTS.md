# Сначала открой хендофф — единое правило

**Перед тем как верстать что угодно, прочитай `design-ref/README.md`.** Это
самодостаточная спецификация всего сайта: 14 маршрутов, состав каждого экрана,
все тексты, логика страницы сертификата, открытые вопросы. Тексты в нём —
боевые, переписывать их нельзя.

Разметку конкретного экрана смотри в
`design-ref/prototype/Золотая середина.dc.html`. Это один файл на 1300 строк,
внутри — все страницы. Нужный кусок ищется грепом по заголовку блока:

    grep -n "isWatches\|isGift\|isContacts" "design-ref/prototype/Золотая середина.dc.html"

Расхождения между README хендоффа и прототипом разбираются с автором макета,
а не «как показалось правильнее». Уже нашли одно: README говорит про три
полоски бургера, в прототипе их две (сделали три, по README).

# Свои CSS-классы — только внутри @layer

**Любое собственное правило в `globals.css` живёт в `@layer base` или
`@layer components`.**

Незалоенное правило перебивает ЛЮБУЮ утилиту Tailwind, независимо от
специфичности — так устроен каскад слоёв. `.btn-primary { display:inline-flex }`
вне слоя выиграл у `hidden desktop:inline-flex`, и кнопка «Записаться» висела
поверх бургера на мобильном.

Исключение одно и намеренное: переключение вариантов главной
(`[data-home-variant]`) оставлено вне слоёв — оно обязано перебивать утилиты.

# Оверлеи не кладутся внутрь шапки

**`position: fixed` внутри `<header>` считается не от окна, а от шапки.**

У шапки есть `backdrop-filter: blur(10px)`, а элемент с backdrop-filter
становится содержащим блоком для фиксированных потомков. Мобильное меню,
пока жило внутри шапки, растягивалось на её 60 px: пункты рисовались поверх
страницы, а фон обрывался под шапкой. Теперь меню — сосед шапки, а не потомок.

То же будет с любым будущим модальником, поповером фильтра и подсказкой.

# fade-up не кладётся на контейнер с фиксированной панелью

**Класс `.fade-up` анимирует `transform`, а элемент с такой анимацией
становится содержащим блоком для `position: fixed` внутри. Фиксированная
панель начинает ездить вместе с прокруткой.**

`fade-up` висел на `<main>` в layout группы `(site)` — то есть ломал `fixed`
на ВСЕХ страницах сразу, а не на одной. Панель оплаты сертификата уезжала
вверх и накрывала шапку; при `sticky` она всплывала туда же, потому что
причина была одна. Снятие `fade-up` с `<main>` и с раскрытого содержимого
`Disclosure` починило обе.

По §10 хендоффа появление нужно экранам успеха, а не странице целиком.
Поэтому `fade-up` остался только на экранах успеха и оверлее меню — внутри
них фиксированных потомков нет. Заводя новый `fixed`, пройдите цепочку
предков и проверьте, что ни у одного нет `transform`, `filter`,
`backdrop-filter`, `perspective`, `will-change` или анимации трансформа.

# Сглаживание шрифта — осознанное расхождение с прототипом

**`-webkit-font-smoothing: antialiased` в проект не возвращается**, хотя в
прототипе эта строка есть и её легко скопировать вместе с остальными стилями.

На macOS она утончает штрихи, а Cormorant Garamond — высококонтрастный
дисплейный шрифт: на 20–24 px в кириллице (логотип в шапке, названия моделей
в карточках товара по §6) его тонкие штрихи становятся волосяными. Без неё
заголовки плотнее. Решение принято заказчиком осознанно, расхождение с
прототипом — намеренное.

Рисунок букв и вес 400 из токенов не менялись: правка чисто рендерная.

**Не чините отрисовку шрифта по режиму отзывчивого дизайна в Safari.** Он
рисует страницу в масштабе и уменьшает, и тонкие засечки в нём всегда
выглядят рваными — на устройстве их видно чистыми. Мы уже потратили на это
круг: по такому скриншоту сглаживание сначала поменяли в одну сторону, потом
чуть не вернули обратно. Проверять — в обычном окне браузера при 100 % или на
живом устройстве.

# Ссылки и basePath — единое правило

**Внутренний адрес (`/watches`, `/files/…`) ставится только через
`next/link` или `asset()`. Обычный `<a href="/…">` ведёт в 404.**

Сайт публикуется на GitHub Pages по адресу `/goldmean.ru`, и Next подставляет
basePath **сам — но только в `next/link` и `next/image`**. В обычном `<a>`,
в `style={{ backgroundImage: url(...) }}`, в `<iframe src>` он не появится.
Локально при пустом basePath это НЕ видно — ошибка вылезет только после
деплоя.

- **`<Link href="/…">`** — внутренние переходы. Работает само.
- **`asset("/файл.pdf")`** — когда нужен именно `<a>` или CSS-`url()`.
- **Обычный `<a>`** — только внешние адреса, `#`, `mailto:`, `tel:`.

**Как проверить перед коммитом:**

    NEXT_PUBLIC_BASE_PATH=/goldmean.ru npm run build
    grep -roE 'href="/(watches|jewelry|services|contacts|gift)[/"]' out --include=index.html

Пусто — чисто. Есть попадания — это будущие 404.

# Три варианта главной

В HTML лежат все три первых экрана, видимый выбирает CSS по атрибуту
`data-home` на `<html>`. Атрибут ставит инлайн-скрипт в `<head>`
(`src/components/home/HomeVariantScript.tsx`) — синхронно, до первой
отрисовки.

Почему не `useSearchParams`: при статическом экспорте сервер не знает query,
и клиентское переключение дало бы вспышку варианта по умолчанию. Заказчик,
открыв `?home=b`, увидел бы сначала `a`. А параметр заведён именно ради показа.

Значение по умолчанию — `variantDefault` в `content/home.json`. `<html>` помечен
`suppressHydrationWarning`: атрибута нет в серверном HTML, и без этого React
ругается при каждой загрузке главной.

**Инлайн-скрипт отрабатывает только при полной загрузке страницы.** Переходы
внутри сайта мягкие: документ тот же, скрипт не перезапускается. Поэтому за
адресом следит ещё и `HomeVariantSync` на самой главной — без него переход с
карточки `/preview` давал адрес `?home=c` и вариант A на экране. Если добавите
третий способ попасть на главную с параметром — проверьте оба пути, полный и
мягкий.

# Фото на главной — демо, перед релизом заменить

Слоты «часы» и «украшения» во всех трёх вариантах первого экрана и фото
блока «Почему в салоне» заполнены снимками из `InBox/pictures`
(`public/home/*-demo.jpg`). **Это демо для показа заказчику.** Права на
снимки неизвестны (похожи на сток и Pinterest), а на часах читается марка
CHARLIE…, которой в салоне нет. Перед релизом — свои снимки или фото из
медиатек дилеров. Путь задаёт поле `src` рядом с `photo` в
`content/home.json`; уберёте `src` — слот снова покажет ТЗ на кадр.

`consultation-demo.jpg` обрезан до 1200×900: исходник был 4:3, дополненный
до квадрата размытыми полосами сверху и снизу.

**Затемнение под текстом в варианте A — слой на всё фото**, а не на блоке с
текстом, и гуще, чем в прототипе (`SCRIM` в `HomeVariantA.tsx`). В
прототипе было `.55 → 0` на блоке с текстом, и на светлом снимке заголовок
«Часы» падал до 1,5:1. Сейчас подобрано под худший случай — чисто белый
кадр: заголовок не ниже 3:1 (фактически ~6), подпись и ссылка не ниже 4,5:1.
У подписи снята прозрачность `.85` из прототипа — с ней мелкий текст не
дотягивал. Меняете высоту блока с текстом или сам текст — перепроверьте
контраст на светлом кадре.

# Страницы показа живут отдельно

`/preview` — страница выбора варианта главной, `PreviewBar` — плавающая панель
поверх сайта. **Это инструменты показа, а не страницы сайта:** в §4 хендоффа
таких маршрутов нет.

Поэтому обвязка сайта (шапка, подвал, sticky-CTA) вынесена в layout группы
`(site)`, а `/preview` лежит снаружи и рисует себя сам. Перед релизом
удаляются три вещи и больше ничего: `src/app/preview/`,
`src/components/preview/` и `content/preview.json`. Панель исчезает вместе с
ними — она показывается только когда в адресе есть `?home=`, а такие ссылки
ставит только `/preview`.

Миниатюры — живые iframe, а не скриншоты: скриншоты устареют при первой же
правке макета, и заказчику покажут вчерашний сайт. Внутри iframe панель
показа не рисуется (`window.self !== window.top`), иначе она была бы видна
на каждой миниатюре.

Панель сквозная: `?home=` есть только на главной, поэтому выбранный вариант
запоминается в `sessionStorage` (`src/lib/preview-mode.ts`) и панель остаётся
видна в каталоге и дальше. Иначе, нажав «Смотреть каталог», заказчик терял бы
путь назад к выбору. Хранилище читается через `useSyncExternalStore`, а не
`useState` в эффекте: так значение попадает в рендер без лишнего каскада и
остаётся общим для всех подписчиков. Крестик на панели выключает режим.

# Группы кнопок и чипов — сетка, не перенос

**На мобильном кнопки во всю ширину столбиком, на десктопе в строку.**
`flex-wrap` обжимал каждую кнопку по её тексту, и ряды получались рваными:
в карточке товара, в пустой выдаче каталога, в шапке марки.

**Чипы одной группы — в сетке с равными ячейками** (`grid grid-cols-N`), а не
во `flex-wrap`. Так номинал сертификата, «Кому доставить» и интервалы
доставки выстраиваются в колонки. У `.chip` поэтому стоит
`justify-content: center`: в ячейке он шире своего текста, и без
центрирования надпись липла бы влево.

**Размер у всех кнопок сайта один: высота 48 px, поля по горизонтали
20 px** — у закрашенных и обводочных, в шапке, в секциях, в панели внизу и в
блоке доверия. Решение заказчика: «пусть будут одинаковыми везде». В
хендоффе было иначе — поля 16×28 в секциях и 12×22 в шапке; до этого решения
на сайте жило семь высот, от 40 до 56 px, и восемь размеров полей.

У `.btn-primary` размер задан в самом классе (`min-height: 48px`,
`padding: 0 20px`), поэтому у закрашенной кнопки своих `px-*`, `py-*`,
`min-h-*` быть не должно. У обводочных общего класса нет — у каждой
`min-h-[48px] px-[20px]` без `py-*`: заводя новую, ставьте то же. Высота —
минимум, а не жёсткое значение: не влезет надпись в строку, кнопка
вырастет, а не обрежет текст. Чипы фильтров и номиналов — не кнопки, у них
свой размер.

**Фильтры каталога — одинаковые внутри группы**, по самому широкому чипу
группы (сетка `grid-flow-col auto-cols-fr` внутри `w-max`). Не на всю
панель: у украшений самый широкий — «Рождение ребёнка» (134 px), и
«Все» / «Себе» такой ширины выглядели бы пусто. См. раздел про каталоги.

**Шапка марки на десктопе — ряд, только когда он помещается целиком.**
Кнопки одинаковой ширины (по самой широкой), переключение — контейнерным
запросом от ширины колонки шапки, а не окна. Кнопка «Записаться на
консультацию» — 268 px: трём кнопкам у украшений нужно 824 px, двум у часов —
546, колонка на 1280 — 557. У часов ряд уже на ноутбуке, у украшений — с окна
~1840 px. Меняете надпись кнопки или поля — пересчитайте пороги в
`BrandHeader`.
`flex-wrap` сюда не возвращать: он ломал ряд как 2+1 кнопками разной ширины.

# Общая кнопка записи прячется за кнопкой страницы

Панель внизу экрана на мобильном и кнопка записи в шапке на десктопе гаснут,
пока главная кнопка самой страницы в кадре. Наблюдатель у них один —
`src/lib/use-page-cta.ts`.
Иначе рядом оказывались две одинаковые акцентные кнопки в одно и то же
место, а на главной в варианте B они совпадали слово в слово.

Кнопки страниц помечены атрибутом **`data-page-cta`** — это явная пометка,
а не поиск по классу или адресу: видно, какая кнопка на странице главная, и
правило не сломается от смены вёрстки. Добавляете странице свою первичную
кнопку на `/contacts` — пометьте её тоже.

Обе не удаляются, а гаснут: `position: sticky` занимает место в потоке, и
удаление сдвигало бы низ страницы, а кнопка шапки при удалении двигала бы
пункты меню. У скрытой снимаются нажатия и она
убирается из обхода с клавиатуры — иначе невидимая кнопка ловила бы касания
по тому, что под ней.

Сброс `covered` — в уборке эффекта, а не в теле: на странице без своей
кнопки наблюдатель не сработает ни разу, и без сброса панель осталась бы
невидимой там, где она нужна.

**Проверять это в скрытой панели браузера бесполезно.** При
`document.hidden` браузер не доставляет события IntersectionObserver вообще
— не срабатывает даже тривиальный наблюдатель. Проверять на живом
устройстве или в открытом окне.

# Кнопка записи — одна надпись везде

**«Записаться на консультацию» — на всех кнопках записи:** в шапке, в панели
внизу, на главной, на страницах марок и в карточках товара. Текст берётся из
`site.cta.label` в `content/site.json` и больше ниоткуда — ключей `book` в
каталогах нет. Так решил заказчик: в хендоффе было три формулировки
(«консультация», «примерка» у часов, «просмотр» у украшений), и одна и та же
по смыслу кнопка выглядела на разных страницах как разные действия.

«Уточнить наличие» и «Перезвоните мне» — другие действия, под это правило не
попадают.

# Лента «Что сейчас в витрине»

Посты настоящие. `scripts/fetch-telegram.mjs` забирает последние посты
публичного канала и кладёт их в `content/telegram-feed.json`, картинки — в
`public/telegram/`. Actions запускают его раз в час, коммитят изменения и
пересобирают сайт.

**Данные лежат в репозитории, а не тянутся во время сборки.** Упади Telegram
в момент деплоя — сайт собрался бы с пустой витриной. Сейчас при неудачной
выкачке скрипт выходит с ошибкой, ничего не трогая, шаг помечен
`continue-on-error`, и сборка идёт с прошлыми постами.

**Разбор держится на HTML публичного превью `t.me/s/<канал>`.** Официального
способа прочитать историю канала без бота-администратора нет. Telegram не
обещает не менять эту разметку, поэтому при пустом разборе скрипт падает, а
не переписывает файл пустотой. Сломается — чинить парсер в скрипте.

**Запросы идут через `curl`, а не `fetch`.** `fetch` в Node не читает
переменные `HTTPS_PROXY` и за прокси молча падает по таймауту.

**В витрину берутся посты со снимками.** Блок называется «Что сейчас в
витрине», и пустая рамка «пост без фотографии» читается там как поломка.

**Дата абсолютная — «17 сентября», а не «сегодня».** Страница собирается
заранее, и «сегодня» означало бы день сборки: остановись расписание — и
подпись начнёт врать.

**Виджет Telegram намеренно не используется:** он принёс бы чужие шрифты и
цвета в макет и внешний скрипт на каждой загрузке.

**Лента сделана на Telegram, а не на Instagram.** Meta признана
экстремистской и запрещена в РФ (§12 п.4), и у посетителя без VPN на месте
ленты была бы пустота.

# Каталоги

Фильтры живут в адресе (§9 хендоффа): ссылку на отфильтрованную выдачу должно
быть можно переслать. Поэтому чипы — настоящие `<Link>`, а не кнопки с
состоянием: работает средний клик, «открыть в новой вкладке» и копирование
адреса. `scroll={false}` обязателен, иначе смена фильтра прыгает в начало.

Фильтрация идёт на клиенте (`WatchCatalog`, `JewelCatalog`), потому что при
статическом экспорте сервер query не знает. Серверная страница отдаёт список,
уже суженный до марки, — клиент доводит его по полу/механизму или
типу/поводу.

**Десктоп: группы и счётчик в одну строку, если помещаются.** Иначе
следующая группа ЦЕЛИКОМ уходит ниже — `flex-wrap` по группам, а не по
чипам, рваного ряда не бывает. У часов одна строка уже с 1024 px (панель
69 px вместо 141), у украшений — две с 1280, три на 1024. Запас на 1024 у
часов — 4 px (893 из 897): добавите чип или удлините надпись — проверьте,
не уехал ли счётчик на вторую строку.

**Телефон: по строке на группу, чипы внутри прокручиваются вбок.** Раньше они
переносились, и на телефоне панель разрасталась до четырёх рядов — 241 px
против нынешних 141. Три вещи, без которых прокрутка не работает: `min-w-0`
на ленте (иначе флекс не даёт себя сжать и строка распирает панель),
внутренняя сетка `w-max` (иначе чипы сожмут по ширине вместо выпуска за край)
и скрытая полоса прокрутки (она съедала бы ту самую высоту). Счётчик стоит
отдельной строкой: в строке с чипами он отбирал у ленты 70 px из 197, и
обрезанный чип упирался в него вплотную.

**Фильтры и выдача лежат в одном контейнере.** Панель фильтров прилипающая,
а `sticky` держит элемент до конца его СОДЕРЖАЩЕГО БЛОКА. Пока панель была
прямым потомком фрагмента, содержащим блоком оказывался весь `<main>`: она
висела над статьёй о марке и над лентой «Что сейчас в витрине», занимая
треть экрана телефона, и якорь на ленту приводил под неё. Общая обёртка
обрывает прилипание там, где кончается каталог. Будете переставлять блоки —
не выносите `FilterChips` из этой обёртки.

**Сетки каталога — `auto-fill`, а не `auto-fit`** (класс `.grid-fill`). Когда
фильтр оставил две карточки из четырнадцати, они должны сохранить свой
размер, а не растянуться на всю ширину. Обратный случай — лента Telegram: там
постов ровно три, и `auto-fill` рисовал бы пустую серую колонку справа, так
что там `auto-fit`.

Марки адресуются слагами из `content/*.json` (`maurice-lacroix`, `lduchen`,
`smolenskie-brillianty`). Слаги заданы явно, а не транслитерацией на лету:
их видно в ревью, и они не поедут от смены правил транслитерации.

Кнопка записи в карточке товара ведёт на `/contacts?interest=…&note=…`:
форма записи сама выбирает раздел (часы / украшения) и показывает строку
«Модель: …» (§7).

**`/jewelry/:brand` и `/jewelry/:id` — один сегмент.** §4 хендоффа кладёт и
страницу производителя, и карточку изделия прямо под `/jewelry`, а для
маршрутизатора это один и тот же динамический сегмент: двух папок `[brand]` и
`[id]` рядом быть не может. Поэтому `src/app/(site)/jewelry/[slug]` сам
решает, слаг это производителя или артикул изделия, и отдаёт нужный экран.
Заводя новый артикул, проверьте, что он не совпал со слагом производителя.

Референс часов в адресе — в нижнем регистре (`l2.893.4.78.6`). Точки в
сегменте безопасны только потому, что `trailingSlash: true` закрывает адрес
слэшем: иначе сервер принял бы сегмент за имя файла.

# Русские названия склоняются

Заголовок «Ещё у {бренда}» в прототипе подставляет название как есть. Для
часовых марок это работает — латинские названия не склоняются («Ещё у
Longines»). Для шести ювелирных производителей получалось «Ещё у Смоленские
бриллианты и других».

Поэтому у ювелирных марок в `content/jewelry.json` есть поле `genitive`.
Заводя нового производителя, заполните и его. То же правило действует для
любого будущего текста, который склеивает название с предлогом.

# Сертификат: оплаты нет

**Главное действие на странице — «Перезвоните мне», а не конструктор.** Форма
обратного звонка стоит первой, конструктор из §8 убран под раскрывашку
«Собрать самому». Причина та же, что и с оплатой: заявку всё равно принимает
человек, а девять полей до кнопки отпугивали — страница была 9948 px, почти
двенадцать экранов телефона. Конструктор сохранён целиком, не урезан: кому
удобно собрать самому — раскрывает.

**Порядок блоков: первый экран → три шага → витрина строкой → заказ.**
Сначала объясняем, что вообще происходит после оплаты, и только потом просим
действия; кто пришёл готовым, минует объяснение кнопкой первого экрана — она
ведёт на `#gift-order`.

**Блока «На что хватит сертификата» на странице нет.** Восемь плиток на 2,5
экрана стояли после формы и ни на что не отвечали. Привязать выдачу к
выбранному номиналу — что и просилось — сейчас нельзя: самые дешёвые часы в
каталоге 42 000 ₽, а цен на украшения заказчик ещё не дал, так что на
номиналах 5 / 10 / 25 тысяч выдача была бы пустой. Вместо блока — строка со
ссылками в каталоги, где цены настоящие и есть фильтры. Тексты и данные блока
не удалены, лежат в `content/gift.json` под `_picksКомментарий`: появятся
цены на украшения и позиции дешевле 42 000 ₽ — блок можно вернуть уже с
привязкой к номиналу.

Итог по высоте: 9948 → 4480 px, с 11,8 экрана телефона до 5,3.

Раскрывашка (`src/components/gift/Disclosure.tsx`) монтирует содержимое
только в открытом состоянии. Так панель оплаты не висит в DOM, пока
конструктор закрыт, и `Escape`/`Tab` не уходят в скрытые поля.

Конструктор собран по §8 полностью, включая валидацию: кнопка активна только
когда есть сумма от минимальной, адрес, дата, интервал, имя, телефон и
согласие. Но **оплаты не существует** — сайт статический, эквайринг идёт
этапом интеграции (§9), канал приёма заявок не выбран (§12 п.7).

Поэтому над экраном успеха стоит полоска-предупреждение. Без неё страница
утверждала бы, что деньги списаны, хотя не ушло ничего. Полоска помечена
комментарием `ДЕМО-ПОЛОСКА` и удаляется одним блоком, когда оплата заработает.

Номер заказа `ЗС-1234` по §8 генерирует сервер. Сервера нет, поэтому номер
пока собирается на клиенте — только ради демонстрации экрана.

**Формулировки условий сертификата юридически значимы** и меняются только с
заказчиком (§8). Они лежат в `content/gift.json`, не в компонентах.

# Логотип салона и фавикон

**В шапке — логотип, а не набранный текст.** С 1280 px — надпись в строку
(`public/logo/goldmean-logo.svg`), уже — круглая эмблема
(`public/logo/goldmean-emblem.svg`), на телефоне тоже эмблема. Пути — в
`site.logo` в `content/site.json`, в `<img>` они идут через `asset()`.

**В подвале — тоже логотип**, надпись в строку на всех ширинах (в подвале
места хватает и на телефоне). Раскладка подвала: телефон — столбик,
планшет — 2×2, с 1024 px — четыре блока в строку по своей ширине с равными
промежутками (`justify-between`). Слоган ограничен 260 px, чтобы шёл в две
строки и не растягивал первый блок.

Почему эмблема и на ноутбуке: надпись шириной 227 px на окнах 1024–1190 px
не оставляла места — пункты меню переносились на две строки, кнопка
сжималась. Эмблема уже на 183 px, и с ней всё встаёт в строку с 1024. У
пунктов меню и кнопки в шапке стоит `whitespace-nowrap`: если места снова
не хватит, это будет видно по вылезшей шапке, а не по тихому переносу.

**Эмблема вырезана из `InBox/logo/goldmean-logo-mini.svg`.** На листе этого
файла под эмблемой лежит ещё и надпись в строку — в шапку она не идёт.
Копия в `public/` обрезана по `viewBox` до эмблемы, надпись удалена,
оригинал не тронут. Два золота в исходниках чуть разные: `#9b7a42` у
надписи, `#8a6d3b` у эмблемы (это `--accent`). Так нарисовал автор.

**Фавикон — из той же эмблемы, с белой заливкой круга** (решение
заказчика). `src/app/icon.svg` —
копия эмблемы с белым `<circle>` под ней, центр и радиус — по кругу-обводке;
`src/app/favicon.ico` (16/32/48) и `src/app/apple-icon.png` (180, на фоне
`--bg`: iOS заливает прозрачное чёрным) нарезаны из
`InBox/logo/goldmean-emblem.png` — тоже с белым кругом. Эмблема в шапке
сайта тоже с белым кругом: `public/logo/goldmean-emblem.svg` и
`src/app/icon.svg` сейчас один и тот же файл — правите один, правьте и
второй. Next сам ставит `<link>` и подставляет basePath.
Прозрачный оригинал растра —
`InBox/logo/goldmean-emblem-transparent.png` (1024 px, прозрачный фон).
Рядом `goldmean-emblem.png` — тот же круг с белой заливкой внутри: для
площадок, где прозрачное становится серым (аватарки в картах и соцсетях).

**ImageMagick эту эмблему рисует неверно:** не понимает общие CSS-правила
вида `.cls-1, .cls-2` (красит в чёрное) и теряет тонкий круг. PNG сделан
отрисовкой в браузере. Пересобираете растр — тоже через браузер.

На 16 px надпись внутри круга не читается — остаётся золотое пятно. Для
вкладки лучше нужен упрощённый знак без текста; это вопрос к автору
логотипа.

# Логотипы марок

Лежат в `public/logo/watches/<слаг>.<ext>`, путь прописан в поле `logo` у
марки в `content/watches.json`. Нет поля — `ImageSlot` рисует плейсхолдер с
подписью, какой файл нужен. Так что новый логотип подключается копированием
файла и одной строкой в json.

**Логотип выводится через `ImageSlot` с `fit="contain"`**, а не `cover`:
логотип надо вписать целиком, не обрезая. При `contain` слот не красит
подложку — логотип лежит на собственном фоне плитки.

**basePath в обычный `<img src>` Next не подставляет** — только в
`next/image`. Поэтому `ImageSlot` прогоняет src через `asset()`. Забудете —
на Pages логотипы отдадут 404, а локально всё будет выглядеть исправно.

Все четырнадцать часовых марок — в SVG. Оригиналы лежат в `InBox/logo/`,
в `public/` — копии под слагами марок.

Два файла пришли под тёмный фон, и на светлой плитке надпись была бы
невидимой. В `public/` белая заливка заменена на `currentColor` — внутри
`<img>` он рисуется чёрным. Оригиналы не тронуты.

- **Raymond Weil** — белый целиком, перекрашен целиком. Лучше запросить у
  поставщика штатную тёмную версию.
- **Swiss Alpine Military** — перекрашена только надпись (класс `st-text`).
  Белый крест на красном щите оставлен белым: это знак марки.

**Не проверяйте перекраску через ImageMagick** — он не понимает
`currentColor` и рисует надпись пустотой. Смотреть в браузере.

Логотипов ювелирных производителей пока нет ни одного.

# Подсказки «?» у характеристик

`content/spec-hints.json` — короткие расшифровки характеристик в карточке
товара. Ключ — название строки ровно так, как его возвращает `watchSpecs()`;
разойдутся — подсказка молча пропадёт.

Это то, что предлагал автор контент-пакета: «каждый пункт можно использовать
как всплывающую подсказку „?"». Поэтому тексты почти все взяты из
`content/info/harakteristiki.md` дословно, а у поля `source` записано откуда.

**`draft: true` — текст собран нами из таблиц справочника, а не написан
автором.** Сейчас таких два: `Корпус` и `Ремешок / браслет` — у этих разделов
в справочнике нет вводной фразы, одни таблицы. Их должен вычитать автор
текстов. Добавляете свою подсказку — ставьте `draft` и ей.

Подсказка раскрывается по КЛИКУ, а не по наведению: на телефоне ховера нет,
и половина посетителей до неё просто не добралась бы.

**Открытых подсказок может быть несколько.** Когда открывалась только одна,
клик по нижней характеристике схлопывал верхнюю — и всё, что выше, уезжало
вверх прямо под курсором. Сейчас клик двигает только строки ниже себя.

Раскрытие плавное: блок всегда в разметке, анимируется высота строки грида
`0fr → 1fr` (класс `.hint-reveal`). Так высоту не нужно измерять заранее, в
отличие от `max-height` с выдуманным потолком, а текст попадает в
статический HTML. Пока закрыто, на содержимое ставится `inert` — иначе
ссылка «подробнее» ловила бы фокус с клавиатуры в невидимом блоке.

«?» прижат к правому краю колонки названий (`justify-between`): иначе он
вставал сразу за словом, а слова разной длины — и кнопки гуляли по
горизонтали вместо ровного столбика.

Ссылка в справочник висит только в подсказке. У значения характеристики своя
ссылка бывает лишь там, где она ведёт в другое место и подсказки нет, —
сейчас это «Производитель» у изделий.

**`href` у подсказки необязателен.** У характеристик украшений
страницы-справочника пока нет: `/diamonds` — заглушка. Там подсказка
показывается без ссылки «подробнее». Свёрстаете `/diamonds` — проставьте
`href` у «Камней», «Металла», «Сертификата».

# Упоминание марки — всегда ссылка

**Название марки ведёт на её страницу везде, где встречается:** в шапке
карточки товара, в подписи под фото в каталоге, в блоке «Ещё у …», в строке
«Производитель». Ставится через `@/components/catalog/BrandLink`, адрес
берётся из `watchBrandHref()` / `jewelBrandHref()` — руками адрес не
собираем, иначе он в каждом месте получится свой.

Из-за этого карточка в блоке «Ещё у …» больше не обёрнута в одну ссылку
целиком: вложенные ссылки недопустимы. Кликабельны фото, название и подпись
марки по отдельности. Если будете добавлять ссылку внутрь карточки товара в
каталоге — проверьте то же самое.

# Справочные страницы /info

`/info/garantia` и `/info/harakteristiki` собираются из `content/info/*.md`
тем же модулем, что и статьи марок. Имя файла — слаг адреса; новый файл в
каталоге сразу становится страницей, ничего дописывать не нужно.

Адреса взяты из контент-пакета: по ним же живут страницы текущего сайта,
значит при переезде не понадобится редирект. В §4 хендоффа этих маршрутов
нет — они пришли вместе с текстами марок, которые на них ссылаются.

**Попасть на них можно из карточки часов и из статей марок**, в подвал и
меню они намеренно не добавлены: §6 фиксирует и то, и другое.

В `garantia.md` четыре пометки `[ПРОВЕРИТЬ]`: три — незакрытые вопросы к
салону (кто ставит печать в талоне, куда обращаться по гарантии, отличается
ли срок у отдельных марок), четвёртая просит проверить ссылку на справочник
после его публикации — справочник опубликован, скобку можно снимать.

# Шрифт текста — Manrope, а не Figtree

В `design-ref/tokens.css` для текста указан **Figtree**. У него в Google Fonts
нет кириллицы, только latin и latin-ext, — а сайт русский целиком. С Figtree
весь текст уходил бы в системный фолбэк: на Mac рисовался бы SF Pro, на
Windows — Segoe, то есть у заказчика и у нас сайт выглядел бы по-разному.

Взяли **Manrope**: геометрический гротеск того же характера, кириллица есть,
те же начертания 300/400/500/600. Подмена сделана в одном месте — в `:root`
в `globals.css`, где значения токенов связываются с именами от `next/font`.
`design-ref/tokens.css` и его копия в `src/styles/` НЕ правятся: это копия
файла из хендоффа, и она должна остаться сверяемой с оригиналом.
