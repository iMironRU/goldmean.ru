# Сначала открой хендофф — единое правило

**Перед тем как верстать что угодно, прочитай `design-ref/README.md`.** Это
самодостаточная спецификация всего сайта: 14 маршрутов, состав каждого экрана,
все тексты, логика страницы сертификата, открытые вопросы. Тексты в нём —
боевые, переписывать их нельзя.

Разметку конкретного экрана смотри в
`design-ref/prototype/Золотая середина.dc.html`. Это один файл на 1300 строк,
внутри — все страницы. Нужный кусок ищется грепом по заголовку блока:

    grep -n "isWatches\|isGift\|isContacts" "design-ref/prototype/Золотая середина.dc.html"

**Прототип — референс, а не код.** Копировать его рантайм (`support.js`,
`image-slot.js`, теги `sc-for` / `sc-if`) в проект нельзя, это прямо записано
в §1 хендоффа. Из него берутся значения: размеры, отступы, цвета, тексты.

Расхождения между README хендоффа и прототипом разбираются с автором макета,
а не «как показалось правильнее». Уже нашли одно: README говорит про три
полоски бургера, в прототипе их две (сделали три, по README).

# Свои CSS-классы — только внутри @layer

**Любое собственное правило в `globals.css` живёт в `@layer base` или
`@layer components`.**

Незалоенное правило перебивает ЛЮБУЮ утилиту Tailwind, независимо от
специфичности — так устроен каскад слоёв. `.btn-primary { display:inline-flex }`
вне слоя выиграл у `hidden desktop:inline-flex`, и кнопка «Записаться» висела
поверх бургера на мобильном.

Исключение одно и намеренное: переключение вариантов главной
(`[data-home-variant]`) оставлено вне слоёв — оно обязано перебивать утилиты.

# Оверлеи не кладутся внутрь шапки

**`position: fixed` внутри `<header>` считается не от окна, а от шапки.**

У шапки есть `backdrop-filter: blur(10px)`, а элемент с backdrop-filter
становится содержащим блоком для фиксированных потомков. Мобильное меню,
пока жило внутри шапки, растягивалось на её 60 px: пункты рисовались поверх
страницы, а фон обрывался под шапкой. Теперь меню — сосед шапки, а не потомок.

То же будет с любым будущим модальником, поповером фильтра и подсказкой.

# Сглаживание шрифта — осознанное расхождение с прототипом

**`-webkit-font-smoothing: antialiased` в проект не возвращается**, хотя в
прототипе эта строка есть и её легко скопировать вместе с остальными стилями.

На macOS она утончает штрихи, а Cormorant Garamond — высококонтрастный
дисплейный шрифт: на 20–24 px в кириллице (логотип в шапке, названия моделей
в карточках товара по §6) его тонкие штрихи становятся волосяными. Без неё
заголовки плотнее. Решение принято заказчиком осознанно, расхождение с
прототипом — намеренное.

Рисунок букв и вес 400 из токенов не менялись: правка чисто рендерная.

**Не чините отрисовку шрифта по режиму отзывчивого дизайна в Safari.** Он
рисует страницу в масштабе и уменьшает, и тонкие засечки в нём всегда
выглядят рваными — на устройстве их видно чистыми. Мы уже потратили на это
круг: по такому скриншоту сглаживание сначала поменяли в одну сторону, потом
чуть не вернули обратно. Проверять — в обычном окне браузера при 100 % или на
живом устройстве.

# Ссылки и basePath — единое правило

**Внутренний адрес (`/watches`, `/files/…`) ставится только через
`next/link` или `asset()`. Обычный `<a href="/…">` ведёт в 404.**

Сайт публикуется на GitHub Pages по адресу `/goldmean.ru`, и Next подставляет
basePath **сам — но только в `next/link` и `next/image`**. В обычном `<a>`,
в `style={{ backgroundImage: url(...) }}`, в `<iframe src>` он не появится.
Локально при пустом basePath это НЕ видно — ошибка вылезет только после
деплоя.

- **`<Link href="/…">`** — внутренние переходы. Работает само.
- **`asset("/файл.pdf")`** — когда нужен именно `<a>` или CSS-`url()`.
- **Обычный `<a>`** — только внешние адреса, `#`, `mailto:`, `tel:`.

**Как проверить перед коммитом:**

    NEXT_PUBLIC_BASE_PATH=/goldmean.ru npm run build
    grep -roE 'href="/(watches|jewelry|services|contacts|gift)[/"]' out --include=index.html

Пусто — чисто. Есть попадания — это будущие 404.

# Три варианта главной

В HTML лежат все три первых экрана, видимый выбирает CSS по атрибуту
`data-home` на `<html>`. Атрибут ставит инлайн-скрипт в `<head>`
(`src/components/home/HomeVariantScript.tsx`) — синхронно, до первой
отрисовки.

Почему не `useSearchParams`: при статическом экспорте сервер не знает query,
и клиентское переключение дало бы вспышку варианта по умолчанию. Заказчик,
открыв `?home=b`, увидел бы сначала `a`. А параметр заведён именно ради показа.

Значение по умолчанию — `variantDefault` в `content/home.json`. `<html>` помечен
`suppressHydrationWarning`: атрибута нет в серверном HTML, и без этого React
ругается при каждой загрузке главной.

**Инлайн-скрипт отрабатывает только при полной загрузке страницы.** Переходы
внутри сайта мягкие: документ тот же, скрипт не перезапускается. Поэтому за
адресом следит ещё и `HomeVariantSync` на самой главной — без него переход с
карточки `/preview` давал адрес `?home=c` и вариант A на экране. Если добавите
третий способ попасть на главную с параметром — проверьте оба пути, полный и
мягкий.

# Страницы показа живут отдельно

`/preview` — страница выбора варианта главной, `PreviewBar` — плавающая панель
поверх сайта. **Это инструменты показа, а не страницы сайта:** в §4 хендоффа
таких маршрутов нет.

Поэтому обвязка сайта (шапка, подвал, sticky-CTA) вынесена в layout группы
`(site)`, а `/preview` лежит снаружи и рисует себя сам. Перед релизом
удаляются три вещи и больше ничего: `src/app/preview/`,
`src/components/preview/` и `content/preview.json`. Панель исчезает вместе с
ними — она показывается только когда в адресе есть `?home=`, а такие ссылки
ставит только `/preview`.

Миниатюры — живые iframe, а не скриншоты: скриншоты устареют при первой же
правке макета, и заказчику покажут вчерашний сайт. Внутри iframe панель
показа не рисуется (`window.self !== window.top`), иначе она была бы видна
на каждой миниатюре.

Панель сквозная: `?home=` есть только на главной, поэтому выбранный вариант
запоминается в `sessionStorage` (`src/lib/preview-mode.ts`) и панель остаётся
видна в каталоге и дальше. Иначе, нажав «Смотреть каталог», заказчик терял бы
путь назад к выбору. Хранилище читается через `useSyncExternalStore`, а не
`useState` в эффекте: так значение попадает в рендер без лишнего каскада и
остаётся общим для всех подписчиков. Крестик на панели выключает режим.

# Каталоги

Фильтры живут в адресе (§9 хендоффа): ссылку на отфильтрованную выдачу должно
быть можно переслать. Поэтому чипы — настоящие `<Link>`, а не кнопки с
состоянием: работает средний клик, «открыть в новой вкладке» и копирование
адреса. `scroll={false}` обязателен, иначе смена фильтра прыгает в начало.

Фильтрация идёт на клиенте (`WatchCatalog`, `JewelCatalog`), потому что при
статическом экспорте сервер query не знает. Серверная страница отдаёт список,
уже суженный до марки, — клиент доводит его по полу/механизму или
типу/поводу.

**Сетки каталога — `auto-fill`, а не `auto-fit`** (класс `.grid-fill`). Когда
фильтр оставил две карточки из четырнадцати, они должны сохранить свой
размер, а не растянуться на всю ширину. Обратный случай — лента Telegram: там
постов ровно три, и `auto-fill` рисовал бы пустую серую колонку справа, так
что там `auto-fit`.

Марки адресуются слагами из `content/*.json` (`maurice-lacroix`, `lduchen`,
`smolenskie-brillianty`). Слаги заданы явно, а не транслитерацией на лету:
их видно в ревью, и они не поедут от смены правил транслитерации.

Карточек товара пока нет, поэтому названия моделей в каталоге НЕ ссылки —
ссылка вела бы в 404. Кнопка записи уже передаёт модель в `/contacts?note=`,
как требует §7: форма подхватит параметр, когда будет свёрстана.

# Данные

**Контент живёт в `content/*.json`, не в компонентах.** Правка текста — правка
одного json, без пересборки логики.

**Данные — только реальные.** Демо-записи из прототипа (`data`, `jewelsData`
в `.dc.html`) — это эталон СТРУКТУРЫ полей, а не контент для импорта: §9
хендоффа говорит об этом прямо. Боевой каталог даёт заказчик. Нет данных —
заготовка с прочерком и комментарием в json, кто заполняет.

# Шрифт текста — Manrope, а не Figtree

В `design-ref/tokens.css` для текста указан **Figtree**. У него в Google Fonts
нет кириллицы, только latin и latin-ext, — а сайт русский целиком. С Figtree
весь текст уходил бы в системный фолбэк: на Mac рисовался бы SF Pro, на
Windows — Segoe, то есть у заказчика и у нас сайт выглядел бы по-разному.

Взяли **Manrope**: геометрический гротеск того же характера, кириллица есть,
те же начертания 300/400/500/600. Подмена сделана в одном месте — в `:root`
в `globals.css`, где значения токенов связываются с именами от `next/font`.
`design-ref/tokens.css` и его копия в `src/styles/` НЕ правятся: это копия
файла из хендоффа, и она должна остаться сверяемой с оригиналом.
